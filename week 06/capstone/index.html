3. Technical Specifications

The model architecture, features, coefficients, and security constraints built into Saad's Content Refresh Scorer.

Model Coefficients (Logistic Regression)

Positive coefficients increase refresh urgency; negative ones suggest traffic stability (evergreen survival bias).

log_impressions_90d (Visibility Volume) +1.27
avg_position (Ranking Depth) -0.40
content_age_days (Time Since Refresh) -0.37
log_clicks_90d (Organic Traffic Clicks) -0.56
users_90d (Telemetry Active Audience) -0.83

Data Safety & Leakage Protections

  • Zero Client Leakage: Client IDs and Page IDs are completely hashed/pseudonymized and kept strictly as metadata grouping variables, never as model features.
  • Label Leakage Exclusions: Explicit outcome trends like trend_direction and trend_pct were dropped entirely to prevent models from memorizing outcome markers.
  • Group-Based Splitting: The validation pipeline splits train/test data based on client_id, ensuring that the model is tested on clients it has never seen before, mirroring production rollouts.

Limitations & Failures Modes

  • Stability Paradox: Highly visible evergreen pages with large room to fall generate false positive refresh triggers, even when search intent is stable.
  • Tail Query Sparsity: Low-volume pages (impressions < 250) suffer from high statistical noise, requiring strict heuristic filters before running the scorer.
  • Competitor Cannibalization: Sudden competitor content pushes generate false negatives since external competitive signals aren't captured by internal GSC/GA4 telemetry.
