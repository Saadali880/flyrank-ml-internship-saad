# Preventing Feature Leakage in Search Click Decline Modeling

In machine learning, feature leakage is one of the most common reasons models fail in production. Feature leakage occurs when training data contains information about the target label that would not be available at the time of inference. In search ranking and SEO click modeling, feature leakage can make a model look exceptionally accurate in testing while rendering it completely useless on live data.

## The Mechanism of Feature Leakage in Click Modeling

When predicting whether a page's clicks will decline in the next month, the target label (e.g., `is_declining_label`) is often constructed using historical traffic changes. For example, a page might be labeled "declining" if its clicks dropped by more than 20% compared to the previous month.

Leakage occurs when features representing the same underlying signal are included in the model. In search click datasets, fields like `trend_direction` or `trend_pct` are frequently included in raw data exports. Because these features are directly calculated from the click changes, they mirror the target label.

If these columns are not removed, a machine learning model (such as a Decision Tree) will immediately identify them as the strongest predictors. During cross-validation, the model will achieve near-perfect precision and recall. However, when deployed, these trend features will not be available (since we are predicting future trends), causing the model's accuracy to collapse.

## Preventing Client Leakage with Group-Based Splitting

Another subtle form of leakage is client leakage. Many SEO datasets contain rows from multiple clients or websites. If we perform a simple random train-test split, rows from the same website will appear in both the training and testing sets.

Websites have distinct traffic patterns, seasonal curves, and domain authorities. If a model trains on some pages from `example.com` and tests on other pages from `example.com`, it will memorize the specific behavior of that site rather than learning general features of click decline. This results in overfitting.

To prevent client leakage, we must use client-level data splitting. This ensures that all pages from a single website or client are kept entirely within either the training set or the testing set, but never both.

## Designing a Leakage Audit

To prevent these issues, developers must implement a leakage audit before training. This audit involves inspecting the features, analyzing correlations, and reviewing how the training data was split. By identifying and removing leaking features early, we ensure the model learns generalizable search ranking behaviors.
